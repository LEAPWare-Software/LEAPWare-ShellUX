## Triage: 3 generic-api-key false positives found before the allowlist

Before adding .gitleaks.toml, `gitleaks git --log-opts=origin/main --redact --no-color .`
found 3 leaks, all rule `generic-api-key`, all in `docs/claims.json`, all from commit
`06ec066` (the register's own introduction in PR A). Re-run without --redact to confirm
what they actually are (raw output, safe to show — these are register field names, not
secrets):

    key": "pr126_medium_fixed"
    key": "pr148_verdict_merge"
    key": "d40_gate_points"

Each is the JSON shape `"key": "<expect-entry-name>"` from a register row's `expect`
list — exactly the shape the `generic-api-key` heuristic flags, and never a credential.
`.gitleaks.toml` now allowlists this exact shape, scoped to `docs/claims.json` only
(see that file's comments for the reasoning), so a real secret added anywhere else in
the file, or under a different shape, is still caught.
