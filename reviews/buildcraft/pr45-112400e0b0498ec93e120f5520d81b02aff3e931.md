### CONFIRMED 1 (blocking). The self-review gate is weaker than on `main`, and a new test locks the weaker behavior in

`_parse_identity` still accepts a stoplisted product name (e.g. "buildcraft", "leapware") sitting in the session-token slot. `_id_segments` then discards that segment before `_shared_long_segment` compares the two ids for a shared long segment — so two ids that differ only in role prefix, sharing no real session token, now pass as independent reviewers where `main` correctly rejects them.

Reproduced at the function level, `main` vs. `pr45`:
```

== pr45 (112400e)
same two ids  shared: None
```

Reproduced end to end in a scratch clone at `pr45`: removed the three existing `reviews/45/` records, added one record with `reviewer_id=reviewer-claude-opus-buildcraft-2026-09-24` and `commit_author_id=author-claude-opus-buildcraft-2026-09-24` (AGREE), committed as LEAPWare with `LWB-Agent: claude`:
```

lwb-lanes check passed   exit=0
== main code, same inputs:
FAIL: reviews/45/f1.json: reviewer_id and commit_author_id share the segment 'buildcraft'
(10 characters, at or above MIN_SHARED_SEGMENT_LENGTH=8) -- likely the same session
or dispatch reviewing its own work, not an independent reviewer
exit=1
```
A single record shaped like this satisfies the "needs 1 independent review" requirement for every content commit on this PR's own branch — i.e. this PR's own self-review protection is checked by a mechanism this same PR weakens.

`tests/test_lwb_lanes.py:1100-1116` (new in this PR) uses `reviewer_id="claude-cto-buildcraft-2026-09-19"` and `commit_author_id="human-reviewer-buildcraft-2026-09-19"` — the same token in the session slot of both — and asserts `errors == []`, i.e. the weaker behavior is asserted as correct rather than caught.

Fix requires either rejecting a stoplisted segment sitting in the session-token slot inside `_parse_identity` (case-insensitively), or treating identical parsed session tokens as self-review regardless of the stoplist — either change requires updating the test above.
