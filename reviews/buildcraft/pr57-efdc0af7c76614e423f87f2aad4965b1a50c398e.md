## Findings

1. **CONFIRMED: the Bash-matcher hook fires in a real, live Claude Code session**, reproduced
   independently in a nested `claude -p` run loading the plugin via `--plugin-dir` from this PR's
   own checkout. The ledger gained exactly one line (`hook_event: PreToolUse, tool_name: Bash`);
   the file did not exist before the run. `git diff --stat` between `main` and this head over
   `plugins/`, `core/`, `adapters/` is empty, so the plugin code exercised is identical to `main`.

2. **CONFIRMED: the Agent-matcher hook fires, and a negative control is clean.** A nested subagent
   dispatch produced a matching ledger line with `tool_name: Agent`, corroborated by the
   transcript's own `subagent_stats`. Running the identical Bash prompt *without* `--plugin-dir`
   produced no ledger file at all — the ledger line is attributable to the plugin, not some other
   hook registration. This negative control does not exist in the PR's own doc; it strengthens
   the claim beyond what the PR itself demonstrated.

3. **Non-blocking: the doc's "isolated" framing undersells a real limitation.** Both of the doc's
   demonstration runs carry the *same* `session_id`, because both were nested child sessions
   inheriting the parent's `CLAUDE_CODE_SESSION_ID`/`CLAUDE_CODE_CHILD_SESSION` environment —
   reproduced identically here. This means (a) `session_id` cannot be used to distinguish the two
   runs from the ledger alone, and (b) the claim is demonstrated only for a nested child session,
   not a top-level one started fresh from a terminal — the doc does not say this, and its "what
   this does not prove" list should.

4. **Non-blocking: some of the doc's supporting evidence is asserted rather than shown.** The
   exact commands and both ledger lines are genuinely in the doc. Not included: a committed
   transcript file (only a cut-down `subagent_stats` fragment appears), and the exact
   `hooks.json` matcher/timeout config in force (named but not quoted). The claim becomes fully
   measured only via independent re-run, which this review supplies for this one environment —
   it does not yet stand on its own as a citation.

5. **Non-blocking but material: the demonstrated case cannot speak to the prior timeout-bug
   class.** `hooks.json` sets `timeout: 10` for both matchers; direct hook invocations here ran
   in ~0.06s because the demo used a non-repo working directory, so only the trivial `lwb_version`
   (always-allow) finding path ever executed — `lwb_proof_required` and other repo-dependent
   branches never ran. The doc says as much for what it does not prove, but never states the
   working directory was outside any repo — the true scope is "non-repo working directory,
   default policy", narrower than the build-plan row's wording.

6. **CONFIRMED: the env-leak fix is real,** verified by reintroducing the literal leaked path and
   confirming `tests/test_lwb_check_env_leak.py::test_success_path_prints_no_needle_count` fails
   without the fix and the suite otherwise passes. Caveat: the tree-scanning half of that test
   only covers `HANDOFF.md`/`README.md` for private-project names; nothing else in its name
   signals this leak-catching role.

7. **CONFIRMED: scope and checklist match.** `git diff main...pr57 --stat` touches exactly the 4
   claimed files. `pytest tests/ -q` → `589 passed, 3 skipped` locally (PyYAML unavailable here;
   the proof record's own environment shows 592, consistent). `lwb_check_proof.py`,
   `lwb_build.py --check`, and `lwb_check_hook_launch.py` all pass at this head.

8. **Low: `HANDOFF.md`'s regenerated block lost CLI/session metadata** (`CLI: unknown`,

## Why AGREE despite the disclosure gaps

None of findings 3–5 dispute the central claim — the hook firing in a live session was
independently reproduced here, with a negative control the original PR lacked. They are
about what the claim covers and how it's cited, which is real but does not block: the
build-plan row and doc should be narrowed (nested-session only, non-repo working directory
only, timeout path unexercised) rather than restated as unconditionally "CONFIRMED."
