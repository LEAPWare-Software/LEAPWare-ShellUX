### 2. My own false-positive on `lwb-commit-identity`, corrected — worth recording in full since it's a caution about this exact clone

I initially found, and was prepared to report as a blocking defect, that `python scripts/lwb_check_commit_identity.py --base origin/main --head HEAD` **fails** locally:
```
FAIL: commit author not LEAPWare or an allow-listed bot: LEAPWare <300127941+LEAPWare-HQ@users.noreply.github.com>
```
21 of the 58 commits I could see in `origin/main..HEAD` carry that identity, which isn't in the script's allow-list (`ALLOWED_HUMAN = ("LEAPWare", "leapware@outlook.com")` exactly, or a `[bot]`-suffixed name). I dug in before charging it: `git rev-parse --is-shallow-repository` → `true`, and `origin/main` (bfe8507) has **zero** parents visible locally (`.git/shallow` names it as the grafted boundary). That means my local `origin/main..HEAD` diff treats `origin/main` as if it had no history at all — so any commit that's genuinely already merged into main's *true*, non-shallow history (like `31a75abfbc23`, literally the repo's original "Bootstrap LEAPWare BuildCraft (lwb) scaffold (#1)" commit, confirmed via the GitHub API to predate this PR by two days) gets miscounted by my clone as "new to this branch." This also explains why my local commit count (58) didn't match the PR API's real count (33 for eb16fed, 34 for the current head) — same shallow-boundary artifact, not a separate discrepancy.

I confirmed this against the real CI log for the exact base/head shas GitHub used:
```
Run python scripts/lwb_check_commit_identity.py --base bfe850796969980545811e1ffa551b9143965faf --head 4d667eb246e2665804563d90857019a9443f7017
```

So `reviews/38/cloud-reviewer.json`'s claim was correct; my first read was a shallow-clone artifact. Recording this because it's the same class of near-miss the repo's own culture asks reviewers to disclose rather than bury.

Note this does **not** put the leak-check finding (#1) at risk: scanning a wider (shallow-inflated) commit range for the leak needle is a superset, not a false-safety net — if the needle isn't found even in the inflated range, it certainly isn't in the true, narrower one.
