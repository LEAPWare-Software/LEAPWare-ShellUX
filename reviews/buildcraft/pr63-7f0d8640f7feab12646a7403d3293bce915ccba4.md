## Summary

The bug is real and the fix is correct and sufficient. Independently
rebuilt the scenario from scratch (mainline commit, side-branch commit
dated after a `-s ours` merge whose first-parent diff is empty, pinned
`GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE`): plain `git log` returned the
side commit; `--first-parent` returned the mainline commit, as claimed.
A second run with the side commit dated earlier showed the bug does not
manifest then, confirming the date-dependence the PR describes.

The production diff really is exactly one line
(`git log --first-parent --format=%H` in `resolve_reviewable_head`) —
nothing else in `scripts/lwb_lanes.py` changed, and `commits_in_range()`
is untouched as claimed.

## Findings

### Confirmed — the 10x-each-way mutation claim reproduces exactly

Removed `--first-parent` with `sed`, ran the new
`test_reviewable_head_walks_first_parent_only_not_a_later_dated_side_commit`
10 times: 10/10 failed (returned the side commit's sha, not mainline's).
Restored with `git checkout -- scripts/lwb_lanes.py`, ran 10 more times:
10/10 passed. Matches the PR's claimed numbers precisely. With the fix
removed, the rest of the suite stayed green except this one test
(1 failed, 80 passed in `test_lwb_lanes.py`) — the pre-existing PR #56
regression test for the related case does not catch this bug on Linux,
corroborating the PR's stated reason for adding a new, date-pinned test
rather than relying on it.

### Confirmed — the test is genuinely non-vacuous

It pins both author and committer dates with explicit `+00:00` offsets on
every commit including the merge, and asserts its own premise before
asserting the fix: that plain `git log` puts the side commit ahead of the
mainline commit, that the side commit is absent from the `--first-parent`
walk, and that `_is_record_only_commit(merge)` is `True` — only then does
it assert the resolved head equals the mainline commit.

### Confirmed — leaving `commits_in_range()` without `--first-parent` is the right call, not an inconsistency

Read `check_lanes`'s use of `commits_in_range`: it walks every commit in a
range to check each one's `LWB-Agent:` trailer, lane, and shared-path
touches. Adding `--first-parent` there would let a bad trailer, wrong-lane
file, or shared-path change on a merged-in side branch go unchecked —
the two functions answer different questions (which commit represents the
PR's reviewable state, vs. which commits need per-commit policy checks),
so the PR's decision to leave one alone is correct, not an unaddressed
loose end.

### Confirmed — the two `verifiable: false` proof exemptions on this branch are honest

`a07ff98` marks a pytest-timing command non-deterministic; the diff itself
shows the recorded elapsed time changing between two runs of the same
command. `22b9e1d` marks a HANDOFF-byte-count command non-deterministic;
a live run today prints a different byte count than the one recorded in
`proof/39.json`, confirming the output is state-dependent. Both are
legitimate uses of the exemption, not a hidden escape hatch.

### PLAUSIBLE, not this PR's — a pre-existing gap in `resolve_reviewable_head`'s fallback

If every commit back to the root is record-only, the walk has no lower
bound and can return a commit from history that predates the PR entirely
(and, on a branch with no lower limit, could walk into `main`'s own
history), which does not match the function's stated fallback behavior of
returning the raw head rather than "walking off into unrelated history."
`--first-parent` narrows but does not fix this. Not reproduced, not
introduced by this PR — worth filing separately since it touches the
same function.

### Noted, not blocking — an unreproduced flaky-looking run

One full-suite run during review showed 16 failures concentrated in
`tests/test_lwb_check_state_claims.py`, a file this PR does not touch;
two subsequent full runs and five isolated runs of that file were clean
(610/610 and 76/76 respectively). Likely environmental (a concurrent
command running at the same time), not attributable to this PR, but
recorded per this repo's own standard against silently discarding an
anomalous result.
